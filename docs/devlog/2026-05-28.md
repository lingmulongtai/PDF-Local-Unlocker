## 実装・修正したこと

- Vite + React + TypeScript + Tailwind CSS の構成を追加
- Reactアプリの初期画面を実装
- ドラッグ&ドロップ、複数PDFキュー、共通パスワード入力、ファイル別パスワード入力を追加
- 状態バッジ、進捗バー、再試行、個別ダウンロード、ZIPダウンロードのUIを追加
- qpdf-wasm Workerの型とプレースホルダーを追加
- パスワードを永続化しない方針をUIとREADMEに明記
- GitHub Actionsで `dist/` をGitHub Pagesへ自動デプロイするワークフローを追加
- Pages artifactに `.nojekyll` が含まれるように `public/.nojekyll` を追加
- qpdf-wasmをWeb Workerへ接続し、`--password=... --decrypt` でPDFを解除する処理を実装
- Workerから返ったPDF bytesをBlobにして、個別ダウンロードとZIP一括ダウンロードへ接続
- qpdfの標準出力と標準エラーをWorker内で捕捉し、ブラウザコンソールに流さないようにした
- qpdf仮想FSの一時ファイルを処理後に削除するようにした
- 重複する解除済みファイル名に `-2`, `-3` を付ける処理を追加
- 処理中にWorkerを停止できるキャンセル処理を追加
- キャンセルされたファイルを `cancelled` 状態として表示し、再試行対象にした
- WebAssembly / Web Worker / Blob URL / crypto.randomUUID の互換性チェック表示を追加
- qpdfの `--show-encryption` でパスワードなしPDFを判定し、`Already unlocked` として扱う処理を追加
- パスワードなしPDFはパスワード未入力でも元PDFをBlob化して、個別ダウンロードとZIP一括ダウンロードの対象にした
- パスワード付きPDFでパスワード未入力の場合だけ `Password required` になるように分岐を整理した
- ZIPなし一括ダウンロード用に `Download PDFs` を追加した
- 各PDF行にプレビューボタンを追加し、Object URLを使ったPDFプレビューモーダルを実装した
- プレビューを閉じたときにObject URLを破棄するようにした

## うまくいかなかったこと

- この環境では通常の `node` / `npm` がWindowsApps側を参照して `Access is denied` になった
- 一時展開したnpm CLIとCodex同梱Nodeを使って依存インストールとビルドを実行した
- ブラウザ自動操作環境ではfile inputへの直接セットが使えず、実ブラウザでのファイル投入までは自動確認できていない
- Vite build時にqpdf-wasm内部のNode向けimportがブラウザ用にexternalizeされる警告が出るが、ビルド自体は成功している
- in-app browserのスクリーンショット取得がタイムアウトしたため、今回はDOM確認のみ記録した
- 自動操作環境の制約で、実ファイル投入後のPDFプレビュー表示と複数ダウンロード許可までは未確認

## 判断したこと

- 初回はqpdf実処理まで入れず、ビルド可能なUIとWorker接続点を優先した
- Viteの `base` はGitHub Pagesで扱いやすいように `./` にした
- Tailwind CSSは公式のViteプラグイン構成にした
- GitHub PagesデプロイはGitHub公式のPages Actionsを使うことにした
- qpdf.wasmは `?url` importでViteにasset管理させることにした
- qpdfの標準出力と標準エラーはWorker内で捕捉し、UI向けの安全な文言だけ返すことにした
- qpdf処理キャンセルはWorker terminateで実装することにした
- 必須ブラウザ機能は起動時にUIへ表示することにした
- ZIPなし一括ダウンロードは個別ダウンロード連続実行で実装することにした
- PDFプレビューはObject URLとiframeで実装することにした
